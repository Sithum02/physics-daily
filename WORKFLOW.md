# Physics Daily — how questions get added

This app is updated through Claude in VS Code. Sithum either:

- **pastes MCQs** ("add these to today"), or
- **asks for new ones** ("make 10 questions on projectiles", "make 10 like these but on circuits").

Claude writes them into the question files, checks them, and publishes. Students see them the next
time they open the app. There is no server and no monthly cost.

> **For Sithum:** you never need to edit these files yourself. Open this folder in VS Code and tell
> Claude what you want. Useful phrases:
> - "Add these 10 MCQs for today: …" (paste them, answers included if you have them)
> - "Make 10 questions for tomorrow on current electricity, A/L standard"
> - "Here are 30 questions, spread them over the next 3 days"
> - "Q4 in today's set is wrong, the answer should be C"
> - "Make 10 questions similar to these: …"

## For Claude: the procedure

### 1. Files

```
data/days/YYYY-MM-DD.json   ← one file per day (the date it unlocks for students)
data/index.json             ← GENERATED by tools/build.mjs. Never edit by hand.
data/img/                   ← diagrams, named YYYY-MM-DD-NN.png
```

A day unlocks when the student's phone date reaches it, so future-dated files are **scheduled posts**.
When given more questions than one day needs, split them across upcoming days (default 10 per day)
unless Sithum says otherwise.

### 2. Day file format

```json
{
  "date": "2026-09-30",
  "title": "Current electricity",
  "questions": [
    {
      "id": "2026-09-30-01",
      "topic": "Current electricity",
      "q": "Question text. x^{2} is superscript, v_{0} is subscript, **bold**, *italic*.",
      "options": ["A text", "B text", "C text", "D text", "E text"],
      "answer": 2,
      "explain": "Worked method shown after answering. End with the answer in **bold**.",
      "image": "data/img/2026-09-30-01.png"
    }
  ]
}
```

- `id` = `<date>-<two-digit position>` (01, 02, …). The build tool enforces this.
- `answer` is 0-based: A=0, B=1, C=2, D=3, E=4.
- Exactly **5 options** (Sri Lankan A/L MCQ style). `image` is optional.
- `title`: a short name for the set, e.g. the main topic or "Mixed revision · Set 4".

### 3. Rules

- **Never change the order or ids of a day students may already have answered** (today or earlier).
  Progress is stored per id on students' phones. To fix a wrong answer or a typo, edit that question in
  place. To add more to today, append with the next ids.
- **Correctness first.** These are for real exam students. For every question Claude writes:
  work the answer out fully, check the arithmetic, make sure exactly one option is right, and make the
  wrong options *plausible* mistakes (wrong formula, °C vs K, forgot to square, unit slip).
- If Sithum pastes a question whose given answer looks wrong, **say so** before publishing. Don't
  silently change it.
- A/L (Sri Lanka) syllabus level, SI units, g = 10 m s⁻² unless the question states otherwise.
- Spread the correct letters across A–E. The build tool warns if a day is lopsided.
- Every question gets an `explain` with the actual working, not just the answer.
- If Sithum gives questions in Sinhala, keep them in Sinhala.

### 4. Check and publish

From the `Mobile App` folder:

```bash
node tools/build.mjs          # validates every file and regenerates data/index.json
git add -A
git commit -m "Questions for 2026-09-30"
git push
```

`build.mjs` exits with errors and writes nothing if something is broken. Fix, then re-run.
GitHub Pages redeploys automatically about a minute after the push.

If app code (`app.js`, `styles.css`, `index.html`) changes, also bump `VERSION` in `sw.js`
so installed apps pick up the new code. Question changes don't need this.

### 5. Preview locally (optional)

VS Code → right-click `index.html` → **Open with Live Server**.
